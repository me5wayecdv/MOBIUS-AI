02 / HOW AGENTS FIND BUGS

An agent is a loop
with a memory of its mistakes.

Each agent has one job and one rule: nothing is a finding until something proves it. The loop is visible, the hypotheses are numbered, and the ones that died are still in the log.

  1. 01

    Observe

    Parse the manifest, map exported surface, read every reachable method.

  2. 02

    Hypothesise

    Write a falsifiable claim: this entry point reaches that sink.

  3. 03

    Probe

    Static trace first, then the cheapest dynamic test that could kill it.

  4. 04

    Verify

    Evidence or nothing. No evidence, no confirmation — mark it undetermined.

  5. 05

    Connect

    Proven hops are joined into a chain; the chain is retested end to end.

Claims need artefacts

A model may propose. Only a trace, a manifest fact or a device capture may confirm. The distinction is enforced in code, not in a prompt.

Uncertainty is a result

Reflection, packed code, dynamic loading: the agent records what it could not resolve instead of filling the gap with a guess.

The loop is auditable

Every step is an event with a timestamp. Replay the run and you get the same chain, the same rejections, the same bytes in the report.

One medium bug
is a ticket.
Five connected
are an incident.

Triage kills real bugs one at a time. MOBIUS models the chain: which entry point an attacker controls, which trust boundary is crossed, which sink turns it into access — and whether the next hop exists at all.

HOP 01

Exported activity

Any app on the device can start DeepLinkRouter. No permission, no caller check.

HOP 02

HOP 03

WebView JavaScript bridge

The loaded page exposes a Java object to JavaScript — and the URL is still attacker-controlled.

CWE-749 · runtime hook

HOP 04

Path traversal in the bridge

readFile() joins a caller-supplied name to the app directory with no normalisation.

CWE-22 · sink proven

HOP 05

Local data exfiltration

Session tokens leave the sandbox through a URL the attacker already controls. Demonstrated, captured, replayable.

PROBLEM 01

Every tool reports the leaf

“Exported activity” without the bridge is noise. “Bridge” without the exported entry is unreachable. Chains are what an attacker actually executes.

PROBLEM 02

Triage measures volume

A thousand findings train a team to ignore the queue. One proven chain with five evidenced hops gives them something to fix before Friday.

PROBLEM 03

Fixes need the whole path

Patch the bridge and hop 2 still leaks. The chain tells you which single hop breaks the most impact — and retests the path after the patch.

Self-host

Docker Compose or a single binary. SQLite for a laptop, Postgres for a team. Runs air-gapped; the analysers do not call home.

02

Bring your model

Point the agent layer at a hosted provider or a local runtime. The model proposes probes; the evidence still has to come from the target.

03

Write an analyser

Analysers and agents are Python interfaces with explicit inputs and evidence contracts. Add a sink, a framework or a whole new agent without forking.

04

Own the output

Findings, chains and reports are files on your disk: JSON, SARIF and a readable HTML report. No export paywall, no hosted dashboard required.

DESIGN NOTES, IN THE OPEN

  • Evidence first. A finding is a row with clauses; each clause names an artefact. No artefact, no clause.
  • Rejected hypotheses are data. They tell you where the analyser was wrong — the most useful thing an agent can leave behind.
  • No hidden model calls. Every call is logged with its purpose, and can be replaced by a rule for the deterministic parts.
  • Reproducible by construction. Same target, same device profile, same chain. If it changes, that is a bug with a test.

06 / QUESTIONS

Reasonable ones.

Is it really open source, or open-core?

Apache-2.0 for the whole engine: analysers, agents, chain builder, report writer and API. There is no closed module that the open one needs.

Does SAST need a model key?

The deterministic analysers — manifest, reachability, gates — do not. Agents use a model for planning and hypotheses; you can point them at a hosted provider, a local model, or disable them and drive the same pipeline by hand.

What does DAST actually run?

Intent replay, deep-link fuzzing, UI driving and Frida hooks on an Android device or emulator you control. Execution is opt-in per run and bound to a signed authorisation for the target.

How is a “chain” different from a vuln list?

A chain is a sequence where each hop is proven and the sequence itself is replayed end to end. It answers “what can an attacker actually do”, not “what did the scanner match”.

What if the agent is wrong?

Its hypothesis is recorded as rejected, with the probe that killed it. Claims without artefacts cannot be promoted to a finding, so a wrong guess costs a log line, not a false positive in your queue.
